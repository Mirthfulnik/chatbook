# Книги-переписки: Telegram Mini App

Одна статичная страница `index.html`. Своего сервера не нужно.

## Где что хранится

| Данные | Где | Почему |
|---|---|---|
| Список книг, прогресс, заметки, герои, тема | Telegram CloudStorage (привязан к пользователю и боту) | Доступно на всех устройствах пользователя |
| Тексты книг | IndexedDB на устройстве | CloudStorage вмещает около 1024 записей по 4 КБ, книга туда не помещается |

Книга узнаётся по содержимому файла. Если загрузить тот же файл на другом устройстве, прогресс, заметки и герои подхватятся.

Вне Telegram (в обычном браузере) всё хранится в localStorage этого браузера.

## Запуск

1. **Разместить страницу по HTTPS.** Проще всего GitHub Pages: создать репозиторий, положить `index.html`, включить Pages в настройках (Settings → Pages → Deploy from branch). Получится адрес вида `https://ИМЯ.github.io/РЕПОЗИТОРИЙ/`.
2. **Создать бота.** В @BotFather: `/newbot`, задать имя.
3. **Подключить Mini App.** В @BotFather: `/mybots` → ваш бот → Bot Settings → Menu Button → указать адрес страницы. Либо `/newapp`, чтобы приложение открывалось по ссылке `t.me/ваш_бот/app`.
4. Открыть бота в Telegram и нажать кнопку меню.

## Поиск героев

Запросы идут напрямую из приложения в API Википедии (`/w/api.php` и `/api/rest_v1/page/summary`), они разрешены для браузеров. Справки из Википедии распространяются по лицензии CC BY-SA, в приложении стоит пометка об источнике.

## Ограничения этой версии

- Проверка подписи `initData` не делается, потому что нет сервера. Это допустимо, пока приложение хранит только данные самого пользователя в его же CloudStorage.
- Очень длинные заметки и большие списки героев занимают несколько записей CloudStorage. Для сотен книг с тысячами заметок лимита в 1024 записи может не хватить, тогда понадобится свой сервер.
- Реплики пока приписываются рассказчику (автору). Разметка диалогов по героям — следующий шаг.

## Аналитика

Все ключи задаются в блоке `window.APP_CONFIG` в начале `index.html`. Пока ключи пустые, аналитика выключена и ничего никуда не отправляется.

### Подключение

1. **PostHog** (поведение внутри приложения). Зарегистрироваться на posthog.com, создать проект, скопировать Project API key (`phc_…`) в `posthogKey`. В `posthogHost` указать регион проекта: `https://eu.i.posthog.com` или `https://us.i.posthog.com`.
2. **Telegram Analytics** (запуски; используется для рейтинга в каталоге Telegram Apps). Написать @DataChief_bot, указать адрес бота и домен, где размещено приложение, и вставить полученные токен и идентификатор в `tgToken` и `tgAppName`.
3. В `idSalt` вписать любую длинную случайную строку и больше её не менять.
4. Для проверки поставить `debug: true`: события будут видны в консоли браузера.

### Что отправляется

Пользователь идентифицируется хэшем SHA-256 от соли и Telegram ID. Имя, юзернейм, сам ID, названия загруженных книг, тексты книг и заметок не отправляются. Автосбор кликов выключен, потому что в кнопках-сообщениях лежит текст книги.

| Событие | Когда | Главные свойства |
|---|---|---|
| `app_open` | запуск | `first_open`, `days_since_last_open`, `opens_total`, `library_size`, `books_reading` |
| `app_hidden` | приложение свернули | `view` |
| `book_upload_started` / `book_added` / `book_upload_failed` | загрузка файла | `format`, `book_lang`, `error` |
| `book_file_restored` / `book_file_missing` | тот же файл на другом устройстве | `pct` |
| `book_opened` | открыта книга | `pct`, `state`, `first_open`, `days_since_last_open` |
| `reading_progress` | пройден очередной порог (по умолчанию каждые 5%) | `pct`, `days_since_start` |
| `reading_session_end` | уход с экрана чтения, сворачивание или 10 минут без «Дальше» | `steps`, `duration_sec`, `start_pct`, `end_pct`, `reason` |
| `book_finished` | дочитан последний шаг | `days_to_finish`, `notes`, `heroes` |
| `toc_jump` | переход по оглавлению | `from_pct`, `to_pct`, `direction` |
| `note_saved` / `note_deleted` / `note_opened_from_list` | заметки | `pct`, `is_edit`, `length` |
| `profile_opened` | открыт профиль книги | `pct`, `heroes`, `notes` |
| `heroes_search` / `heroes_article_parsed` / `heroes_added` / `heroes_search_failed` | поиск героев | `method`, `wiki_lang`, `results`, `found`, `added` |
| `hero_viewed` / `hero_removed` / `hero_wiki_link` | работа со списком героев | `source` |
| `library_search` / `library_filter` | поиск и фильтры в библиотеке | `query_length`, `results`, `filter` |
| `theme_changed` | смена темы | `theme` |
| `book_reset` / `book_removed` | сброс прогресса, удаление | `pct_before`, `notes`, `heroes` |

Ко всем событиям добавляются `in_telegram`, `tg_platform`, `tg_version`, `app_version` и, если приложение открыто по ссылке с меткой, `start_param` (первая метка пользователя сохраняется как `first_start_param`).

### Готовые отчёты в PostHog

- **Популярность:** Trends → событие `app_open` → Unique users, по дням / неделям / месяцам. Отношение DAU/MAU — в Trends через формулу.
- **Возвраты:** Retention → стартовое событие `app_open` с `first_open = true`, возвратное `reading_progress` (возвращаются именно читать, а не просто открывают). Периоды: день и неделя.
- **Как часто читают:** Trends → `reading_session_end` → Unique users, разбивка по количеству сессий на пользователя за неделю; медиана `days_since_last_open` в `book_opened`.
- **Прогресс чтения:** Funnels → `book_added` → `book_opened` → `reading_progress` (pct ≥ 10) → `reading_progress` (pct ≥ 50) → `book_finished`.
- **Где бросают:** Trends → `reading_progress` → Unique users, разбивка по `pct`. Резкий спад между соседними порогами показывает место, где книги бросают.
- **Функции:** Trends по `note_saved`, `heroes_added`, `toc_jump`, `profile_opened` в долях от активных пользователей. Затем Retention с фильтром по когорте «сохранил хотя бы одну заметку», чтобы сравнить удержание.
- **Источники:** любую из диаграмм разбить по `first_start_param`. Ссылки для рекламы: `t.me/ваш_бот/app?startapp=метка`.

### Политика конфиденциальности

Раз приложение собирает статистику, в описании бота нужна ссылка на политику конфиденциальности. В ней стоит перечислить сервисы (PostHog, Telegram Analytics), что собирается (список выше) и что не собирается (тексты, заметки, личные данные). В приложении под библиотекой автоматически появляется короткое уведомление, как только аналитика включена.

## Игра «Путь на Олимп»

Виджет в правом нижнем углу библиотеки — бог-покровитель читателя. Нажатие открывает карту пути на Олимп, шестерёнка на карте — настройки.

### Правила

- Читатель выбирает бога (14 вариантов: двенадцать олимпийцев, Аид и Гестия), дневную норму (5, 10, 15, 30 или 50 сообщений) и ритм (каждый день, через день, раз в три дня).
- Каждое прочитанное сообщение даёт силу. Половина нормы продвигает бога на одну клетку, не больше 6 клеток в день.
- Дорога — 56 клеток на доске 8 × 16. На ней 14 стражей: 8 чудовищ (Сфинкс, Химера, Минотавр, Лернейская гидра, Медуза Горгона, Полифем, Цербер, Тифон), 5 богов Олимпа и хозяин трона — Зевс, а если выбран Зевс, то Кронос.
- Сила стража — сколько сообщений нужно прочитать, чтобы его победить: от 1 дневной нормы у Сфинкса до 4,5 у хозяина трона.
- Если ритм нарушен, бог отступает на 3 клетки за каждый пропущенный день сверх допустимого. Побеждённые стражи остаются побеждёнными.
- С трона Олимпа свергают при первом же нарушении ритма, и хозяина трона придётся победить снова.

Все числа собраны в начале модуля игры (`RETREAT`, `MAX_MOVES`, `SLOTS` с силой стражей, `GOALS`, `RHYTHMS`) и меняются в одном месте.

### Хранение и аналитика

Состояние игры лежит в CloudStorage под ключом `g`, журнал чтения по дням хранится за последние 60 дней. События аналитики: `game_started`, `game_settings_changed`, `game_reset`, `game_daily_goal`, `game_guardian_defeated`, `game_throne_reached`, `game_retreat`, `game_dethroned`, `olympus_opened`, `olympus_guardian_viewed`. С ними можно сравнить удержание игроков и тех, кто не включал игру.
